## Configure the remote

Create an S3 bucket in your AWS account and dedicate one prefix to each job. The TOML contains `remote:bucket/prefix`, storage class and `rclone_config`; [rclone.example.conf](../rclone.example.conf) defines remote `aws`, provider AWS, the bucket region and `env_auth=true`. Match the real bucket region.

Keep AWS keys outside Git. On a workstation, use `~/.aws/credentials`:

```ini
[sambinha]
aws_access_key_id = YOUR_KEY
aws_secret_access_key = YOUR_SECRET
# Temporary credentials only:
# aws_session_token = YOUR_TOKEN
```

```bash
chmod 700 ~/.aws
chmod 600 ~/.aws/credentials
export AWS_PROFILE=sambinha
sambinha --job documents-s3 --dry-run
```

AWS CLI can create a profile with `aws configure --profile sambinha`; it is not an application dependency. Prefer temporary IAM role credentials on EC2/ECS. Restrict IAM access to the bucket/prefix: listing, reads, uploads and deletions; history copying requires reads and writes. Glacier restoration needs `s3:RestoreObject`.

## Private environment files

```bash
mkdir -p ~/.config/sambinha
touch ~/.config/sambinha/secrets.env
chmod 600 ~/.config/sambinha/secrets.env
```

Edit this file with a text editor, using placeholders only in versioned examples:

```bash
export AWS_PROFILE='sambinha'
export CRONITOR_URL='https://cronitor.link/p/YOUR_TOKEN/YOUR_MONITOR'
```

Alternatively use `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and, for temporary credentials, `AWS_SESSION_TOKEN`. Do not combine a profile and inline credentials unintentionally.

```toml
[backup]
secrets_file = "~/.config/sambinha/secrets.env"
cronitor_url = "${CRONITOR_URL}"
```

Input accepts `NAME=value`, optional `export`, quotes, comments and multiline strings. Values are literal: no shell execution or expansion inside the file. Missing/invalid UTF-8, duplicate names, NULs, invalid assignments and incomplete quotes fail with redacted line diagnostics. Inherited terminal values take priority, including empty ones. An explicit TOML Cronitor URL still has priority over the variable. The loaded environment is private to this configuration/subprocesses.

`--secrets-file PATH` selects another file; relative paths are based on the TOML directory. `--secrets-file ""` disables it for one invocation. Without `secrets_file`, normal inherited environment behavior remains. Without a Cronitor URL, notifications are disabled. `.env`, `.env.*`, `secrets.env`, `sambinha.toml`, `.aws`, state and logs are ignored by Git. The [specification](specification.md) uses environment references, never a private endpoint.

## Integrity checks without downloads

`sambinha verify --job documents-s3` and scheduled checks use only object metadata through `rclone lsjson --stat --hash`. Sizes and MD5 are compared with the local active index; new batch controls include the compressed archive size/MD5. JSON control objects are also checked. No object bodies, controls or recovery indexes are downloaded by verification, including failure cases. Metadata requests can still incur API charges.

For a small single-part object, rclone can use its ETag as MD5. Multipart/encrypted objects may require rclone's `X-Amz-Meta-Md5chksum` metadata; a multipart ETag is not the whole-file MD5. Keep checksum metadata enabled; do not configure `--s3-disable-checksum`. Missing hashes or missing local/archive checksum data produce an explicit error, without body-download fallback. This check does not decompress members. [rclone hash behavior](https://rclone.org/s3/#hashes).

Actual `restore` downloads selected objects or full selected archives and can incur retrieval charges. Make GLACIER/DEEP_ARCHIVE objects readable through AWS restore first. Integrity checks themselves never trigger a Glacier restore request.

## Storage classes and costs

The default **GLACIER_IR** offers immediate retrieval, retrieval charges, a 90-day minimum billed duration and 128 KiB minimum billed object size. JSON controls and `.sambinha/control.tar.gz` always use STANDARD so the recovery index is readily available.

| Class | Access and billing considerations |
| --- | --- |
| STANDARD | Immediate; higher storage rate; no cold-storage minimum duration |
| STANDARD_IA / ONEZONE_IA | Immediate; retrieval charges, 30-day minimum; ONEZONE uses one zone |
| INTELLIGENT_TIERING | Automatic tiering and monitoring costs for eligible objects |
| GLACIER_IR | Immediate; 90-day minimum and retrieval charges |
| GLACIER | Asynchronous restore in minutes/hours; 90-day minimum |
| DEEP_ARCHIVE | Restore in hours; 180-day minimum |

GLACIER/DEEP_ARCHIVE are supported for batch storage. Simple backups require immediately readable storage for preserving history. Application retention of 2/10 days can cause early-deletion charges in archival classes; it does not cancel AWS billing minimums. Rates depend on region, data and requests. [AWS storage classes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/storage-class-intro.html), [rclone S3 backend](https://rclone.org/s3/).

Start with `sambinha --job documents-s3 --dry-run`; only an invocation without simulation sends the first backup. Source and staging disk occupancy are monitored locally; S3 exposes no destination-disk occupancy percentage.
