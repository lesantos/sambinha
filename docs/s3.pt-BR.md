# Guardando uma cópia no Amazon S3

[English](s3.md)


O S3 permite guardar uma cópia fora do computador. Para começar, crie um bucket na sua conta AWS e use uma pasta exclusiva dentro dele para cada tarefa. Você também precisará indicar ao rclone a região do bucket e como obter as credenciais. Os exemplos abaixo completam a configuração apresentada no [README](../README.pt-BR.md).

## S3 e credenciais fora do Git

O TOML contém o destino `remote:bucket/prefixo`, a classe de armazenamento e a referência `rclone_config`. [rclone.example.conf](../rclone.example.conf) completa a conexão: remote `aws`, provider AWS, região e `env_auth=true`. Crie o bucket previamente e ajuste a região para a região real do bucket. Cada job precisa de prefixo exclusivo.

A configuração versionada **não contém chaves AWS**. Com `env_auth=true`, o rclone usa a cadeia de credenciais AWS. Para uma máquina pessoal, configure um perfil fora deste projeto, em `~/.aws/credentials`:

```ini
[sambinha]
aws_access_key_id = SUA_CHAVE
aws_secret_access_key = SEU_SEGREDO
# Se forem credenciais temporárias:
# aws_session_token = SEU_TOKEN
```

Proteja esse arquivo e selecione o perfil:

```bash
chmod 700 ~/.aws
chmod 600 ~/.aws/credentials
export AWS_PROFILE=sambinha
.venv/bin/python -m sambinha --job documents-s3 --dry-run
```

Se usar AWS CLI, `aws configure --profile sambinha` cria o perfil de forma interativa; AWS CLI não é uma dependência do aplicativo. Em EC2/ECS, prefira uma **role IAM**, com credenciais temporárias e sem chaves em arquivos. Limite a política IAM ao bucket/prefixo de backup: listar o bucket, ler, enviar e apagar objetos; cópias de histórico precisam de leitura e escrita. Para restaurar Glacier Flexible/Deep Archive, também é necessário `s3:RestoreObject`.

## Arquivo privado de variáveis

Você pode reunir as variáveis que o Sambinha e o rclone vão usar em um arquivo privado, sem carregá-lo manualmente no terminal. Crie e proteja esse arquivo:

```bash
mkdir -p ~/.config/sambinha
touch ~/.config/sambinha/secrets.env
chmod 600 ~/.config/sambinha/secrets.env
```

Edite-o com um editor de texto. O endpoint Cronitor contém um token, por isso também fica nesse arquivo, fora do repositório:

```bash
export AWS_PROFILE='sambinha'
export CRONITOR_URL='https://cronitor.link/p/SEU_TOKEN/SEU_MONITOR'
```

Se você preferir guardar as credenciais AWS diretamente no arquivo, substitua `AWS_PROFILE` por:

```bash
export AWS_ACCESS_KEY_ID='SUA_CHAVE'
export AWS_SECRET_ACCESS_KEY='SEU_SEGREDO'
# Apenas para credenciais temporárias:
# export AWS_SESSION_TOKEN='SEU_TOKEN'
```

Na seção `[backup]` do TOML, configure:

```toml
secrets_file = "~/.config/sambinha/secrets.env"
cronitor_url = "${CRONITOR_URL}"
```

O Sambinha lê o arquivo antes de resolver os caminhos e a URL do Cronitor, e passa as variáveis ao rclone. `env_auth=true` continua necessário na configuração S3 do rclone. Variáveis já presentes no terminal têm prioridade, inclusive se estiverem vazias. Uma URL explícita no TOML também continua tendo prioridade sobre `CRONITOR_URL`; use a referência do exemplo ou remova a linha para ler a variável automaticamente.

O formato aceita atribuições `NOME=valor`, aspas simples ou duplas, comentários e `export` opcional. Os valores são literais, sem executar comandos nem expandir outras variáveis dentro do arquivo. Nomes inválidos, variáveis sem atribuição, nomes repetidos, caracteres nulos ou aspas incompletas interrompem a execução com uma mensagem que indica a linha, sem mostrar seu conteúdo. Um arquivo ausente, ilegível ou fora da codificação UTF-8 também interrompe a execução, inclusive em simulação.

Você pode escolher outro arquivo com `--secrets-file CAMINHO`. Caminhos relativos partem da pasta do TOML; `--secrets-file ""` desativa a leitura apenas naquela execução. As variáveis carregadas ficam isoladas naquela configuração e não alteram o ambiente do terminal. Configurações sem `secrets_file` continuam usando o ambiente normalmente.

Sem URL, notificações ficam desabilitadas. A URL nunca aparece nos logs de notificação. Arquivos `.env`, `.env.*` e `secrets.env` são ignorados pelo Git, assim como `sambinha.toml`, `.aws/`, estado e logs; mantenha as credenciais fora do projeto e os exemplos públicos sem segredos. A [especificação versionada](specification.pt-BR.md) substitui o endpoint privado por uma referência de ambiente.

## Classes S3 e custo

O padrão é **GLACIER_IR**: armazenamento frio com acesso imediato, cobrança por recuperação, duração mínima faturada de 90 dias e tamanho mínimo faturado de 128 KiB por objeto. Controles JSON e `.sambinha/control.tar.gz` usam sempre **STANDARD**, para consultar e recuperar o índice sem restore.

| Classe | Acesso e características |
| --- | --- |
| STANDARD | Imediato; maior custo de armazenamento; sem duração mínima de arquivo frio |
| STANDARD_IA / ONEZONE_IA | Imediato; cobrança de recuperação e mínimo de 30 dias; ONEZONE usa uma zona |
| INTELLIGENT_TIERING | Transição automática; custos de monitoramento conforme tamanho elegível |
| GLACIER_IR | Frio, acesso imediato; mínimo de 90 dias e cobrança de recuperação |
| GLACIER | Restore assíncrono em minutos/horas; mínimo de 90 dias |
| DEEP_ARCHIVE | Restore em horas; mínimo de 180 dias |

`GLACIER` e `DEEP_ARCHIVE` são aceitos para `batch`. `simple` exige classe acessível sem restore, pois precisa copiar versões antigas antes de substituir o objeto. Retenção de 2/10 dias em classes frias pode gerar cobrança de exclusão antecipada; retenção da aplicação não cancela a duração mínima faturada. Custos variam por região, volume e operações. Veja [classes S3 da AWS](https://docs.aws.amazon.com/AmazonS3/latest/userguide/storage-class-intro.html) e [backend S3 do rclone](https://rclone.org/s3/).


Com a configuração pronta, execute primeiro uma simulação com `sambinha --job documents-s3 --dry-run`. Ela verifica as ferramentas e lê as informações necessárias; o primeiro envio real só acontece quando você executa sem `--dry-run`.

## Verificação sem downloads

`sambinha verify --job documents-s3` e as verificações agendadas usam apenas metadados via `rclone lsjson --stat --hash`, comparando tamanho e MD5 com o índice ativo local. Novos controles de lotes incluem tamanho/MD5 do arquivo compactado; controles JSON também são conferidos. Nenhum corpo de objeto, controle ou índice é baixado pela verificação, inclusive em falhas; consultas ainda podem gerar cobrança de API.

ETag de objeto pequeno single-part pode ser MD5. Multipart/criptografia podem exigir `X-Amz-Meta-Md5chksum`; ETag multipart não é MD5 do arquivo inteiro. Mantenha esse metadado habilitado; não configure `--s3-disable-checksum`. Hash/índice local/checksum de lote ausente causam erro explícito, sem baixar conteúdo. A checagem não extrai membros. Veja o [comportamento de hashes do rclone](https://rclone.org/s3/#hashes).

`restore` efetivamente baixa arquivos/lotes selecionados e pode gerar custos; GLACIER/DEEP_ARCHIVE exigem restore prévio da AWS. A verificação nunca solicita restore Glacier. Discos da origem e staging são monitorados localmente; S3 não expõe porcentagem de ocupação de disco de destino.
