# Architecture

[Português do Brasil](architecture.pt-BR.md)

`config` keeps the configuration models, TOML/environment loading and CLI overrides. `config_validation` groups global, job, job-path and cross-job destination validators, preserving the order and wording of errors. `paths` shares overlap rules without coupling restoration to TOML loading. `cli` dispatches backup, restore and verification with stable exit codes. `inventory` defaults to metadata-only size/mtime records; hash mode calculates fingerprints using validated cache entries and periodic full scans. Both detect concurrent metadata changes. `batches` is a pure planner: directories, oldest-first ordering, stable previous membership and profile boundaries. `profiles` maps filenames to separate text/video/photo/other settings.

`storage.Storage` retains the public adapter contract, exact-object operations and mutation preconditions. `rclone` builds command arguments and forwards retry/progress/output options to the runner. `simple_storage.SimpleStorageMixin` implements tree sync, run history, native checks and selected restores through the adapter's `path`/`command` contract. This separation lets command transport and storage policy evolve independently while retaining the existing `Storage` entry points. `process` supplies bounded retries/timeouts and redacted errors without shell interpolation; its `Runner` tracks every live child in a cancellation token shared with worker copies, spawns children in their own session and, on `cancel()`, terminates then kills those process groups so blocked runs raise an interruption instead of retrying. `handle_termination` turns SIGTERM in the main thread into `Terminated` (a `KeyboardInterrupt`), so backup and recovery unwind through the same finally/`__exit__` blocks as Ctrl+C: the end event is logged with `success=false`, staging directories and the discovery server are released, and the CLI exits 143 (130 for Ctrl+C). Batch upload workers check the token before compressing and before each upload; an interruption in the main thread cancels the shared runner so in-flight 7-Zip/rclone children die and the pool drains in seconds. `state` validates complete indexes, atomically writes private JSON and locks a single writer. `logging` writes private JSONL audits and redacts values before serialization. `notify` handles optional Cronitor telemetry. `names` centralizes the `.sambinha` namespace, history/index/control keys, the `state.json` file name, the rclone namespace exclude filter and the `Literal` aliases for job logic, storage type, verification mode and CLI action; it imports nothing from the package. `errors` adds `ForeignStateError` and `UnsupportedStateError` so recovery re-raises identity/schema failures by type instead of matching message substrings. `local_paths.reject_symlinks` is the single check used by state, metadata, restore and recovery paths to refuse symlinked metadata files or ancestors. `session.open_session` builds the shared `Runner`, redactor, `Progress` and `RunLog` for `engine.run` and `recovery.recover`, prunes expired logs on request and closes progress/log after the caller's end event.

`secrets` uses the [python-dotenv parser](https://github.com/theskumar/python-dotenv) to validate a whole file as data. Inherited environment variables take priority; no shell execution or parent-environment mutation occurs. The same private environment reaches dependency lookup and subprocesses. The internal environment field cannot be supplied through TOML or exposed by configuration representations.

`engine` owns the run lock, telemetry, job order and failure policy. `jobs.JobExecution` owns a single job's frozen rules, preflight, strategy, scheduled verification and summary. `preflight` separates destination validation from source discovery and returns a tuple-compatible `JobInventory` with named fields. `context.Context` owns per-job state, metrics, removal guards and retention. `archives` compresses directly from the source and validates batch members; `strategies.simple` manages native sync/history and `strategies.batch` separates planning, upload selection, bounded workers and transactional index publication.

Strategy plugins registered in `engine.STRATEGIES` still receive `Context`, with job/configuration, inventory, state, storage and log. Existing `engine` imports for `Context`, `preflight`, `DAY`, progress and batch helpers remain available. New strategies/backends must extend configuration validation and the Storage contract. `state.identity` (job name, type, logic, namespace and S3 destination; `state.identity_matches` accepts legacy or adopted identities, `state.record_origin` keeps per-host origins) and `state.indexed_files` define index ownership and active file lookup for both backup and recovery; `index_generations` writes the `.sambinha/job.json` marker and re-adopts the remote index when its generation differs from the local state; recovery keeps its previous import entry points. No module needs to import the engine to perform a lower-level operation.

Simple jobs delegate traversal, exclusions and synchronization to one `rclone sync` command. A unique `--backup-dir` under `.sambinha/history/` retains replaced/deleted files until the larger of `deleted_days` and `version_days`; finalization lists immediate history directories and purges expired runs. `--max-delete` is an absolute per-job cap and the entire sync is not retried. Batch keys are immutable and derived from original indexed metadata; the planner reuses compatible intact archives. Worker threads own separate subprocess state and staging. The main thread publishes the recovery index only after all uploads, then commits local state. Batch retention cleanup uses `index_pending` to retry publication after failures.

`filtering` freezes rules and delegates matching to rclone, including historical paths represented by empty files. For batch jobs with exclusions, `discovery` owns one authenticated loopback-only `rclone rcd` process and calls non-recursive `operations/list` per directory over a persistent HTTP connection. A fixed filesystem root preserves anchored native filters and avoids dummy source trees. Each directory uses one synchronous request with an independent deadline, without asynchronous job polling or sleeps. The server is stopped/reaped on failure or interruption. Discovery and file inspection share one sequential mtime/name DFS walk: selected children are inspected relative to open no-follow directory descriptors, without a second source traversal or repeated ancestor checks per file. Source symlinks, including broken links and directory cycles, are ignored; their targets are never followed. From 0.14.3, known native FAT/exFAT devices may change only an unpinned historical inode number when all other observed metadata agrees. Directory checks after traversal compare the pathname with the still-open descriptor, rather than the older listing inode. Files are pinned through metadata/hash inspection and final descriptor/path checks; simple mode uses `O_PATH` without reading contents. Fingerprint-cache signatures stay strict. Comparison failures include stage and before/after device, inode, type, size, times and mode; unknown filesystem information never relaxes validation. Hash caches and before/after signatures still detect file changes, and replaced directories abort the walk. Counters remain indeterminate until discovery finishes. The complete batch inventory is still assembled before planning, so partial discovery never reaches uploads, deletion planning or state publication. Historical names continue to use dummy trees because those paths may no longer exist. Results are cached per Selection per execution. Legacy mixed excluded batches stay in `excluded`. `retention` stores deadlines/original paths and aggregates advisory warnings; the separate removal guard blocks large inventory losses before strategy execution. `mounts` checks pinned nonempty volumes, and `disks` rejects local filesystems above 95% occupancy before backup and destination changes.

`recovery` dispatches recovery actions, handles locking/logging/failure policy and preserves its original function imports. `recovery_index` reads local indexes or a bounded remote recovery member; `archive_recovery` validates checksums and safe archive members before extraction. `restore` stages selected files and publishes only after all checks pass; `verification` handles native checks, local archive integrity and S3 object metadata. Simple verification invokes `rclone check`; batch checks verify archives and controls. Daily batch verification reads only source/local control metadata; `verify-destination-metadata` checks JSON replicas and archive size metadata, and manual `verify-destination-integrity` lists/tests actual archives. `metadata` owns the configurable JSON mirrors and identity-bound active catalog. Only successful scheduled batch checks update their timestamp.

`progress` displays throttled stage/directory/percentage updates only on interactive stderr. Simple sync uses rclone's live stats; batch inventory counters use files/bytes and other opaque subprocesses use bounded estimates. `logging` clears the transient line before printing JSON; progress has no audit event.

The writer lock covers backup execution and manual verification. Restore reads an atomic index snapshot and fails if a concurrently retired object is unavailable. Without filesystem snapshots, concurrent source changes can interrupt a backup. Jobs are independently committed; there is no distributed transaction across jobs. Overlapping jobs follow TOML order and may invalidate each other's indexes or overwrite a shared remote recovery control; preserving local state and using dedicated prefixes avoids those interactions. Fingerprint reuse assumes honest local filesystem metadata; complete periodic scans are the fallback.


## Batches and recovery in 0.13.0

See [stable batches, uniform compression, final Cronitor alerts, manual rebalance and generation recovery](batch-lifecycle.md) for current behavior and migration from 0.12.0.

`index_generations` validates/recovers state before planning and publishes confirmed generations using a journal/checksum. `rebalance` stages only oversized destination archives without the source, sharing publication/retention. `batch_alerts` collects growth messages for final telemetry; `batches` preserves logical IDs/membership with dedicated-file diversion and byte-only packing.
