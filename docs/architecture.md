# Architecture

[Português do Brasil](architecture.pt-BR.md)

`config` keeps the configuration models, TOML/environment loading and CLI overrides. `config_validation` groups global, job, job-path and cross-job destination validators, preserving the order and wording of errors. `paths` shares overlap rules without coupling restoration to TOML loading. `cli` dispatches backup, restore and verification with stable exit codes. `inventory` defaults to metadata-only size/mtime records; hash mode calculates fingerprints using validated cache entries and periodic full scans. Both detect concurrent metadata changes. `batches` is a pure planner: directories, oldest-first ordering, stable previous membership and profile boundaries. `profiles` maps filenames to separate text/video/photo/other settings.

`storage.Storage` retains the public adapter contract, exact-object operations and mutation preconditions. `rclone` builds command arguments and forwards retry/progress/output options to the runner. `simple_storage.SimpleStorageMixin` implements tree sync, run history, native checks and selected restores through the adapter's `path`/`command` contract. This separation lets command transport and storage policy evolve independently while retaining the existing `Storage` entry points. `process` supplies bounded retries/timeouts and redacted errors without shell interpolation. `state` validates complete indexes, atomically writes private JSON and locks a single writer. `logging` writes private JSONL audits and redacts values before serialization. `notify` handles optional Cronitor telemetry.

`secrets` uses the [python-dotenv parser](https://github.com/theskumar/python-dotenv) to validate a whole file as data. Inherited environment variables take priority; no shell execution or parent-environment mutation occurs. The same private environment reaches dependency lookup and subprocesses. The internal environment field cannot be supplied through TOML or exposed by configuration representations.

`engine` owns the run lock, telemetry, job order and failure policy. `jobs.JobExecution` owns a single job's frozen rules, preflight, strategy, scheduled verification and summary. `preflight` separates destination validation from source discovery and returns a tuple-compatible `JobInventory` with named fields. `context.Context` owns per-job state, metrics, removal guards and retention. `archives` snapshots, compresses and validates batch members; `strategies.simple` manages native sync/history and `strategies.batch` separates planning, upload selection, bounded workers and transactional index publication.

Strategy plugins registered in `engine.STRATEGIES` still receive `Context`, with job/configuration, inventory, state, storage and log. Existing `engine` imports for `Context`, `preflight`, `DAY`, progress and batch helpers remain available. New strategies/backends must extend configuration validation and the Storage contract. `state.identity` and `state.indexed_files` define index ownership and active file lookup for both backup and recovery; recovery keeps its previous import entry points. No module needs to import the engine to perform a lower-level operation.

Simple jobs delegate traversal, exclusions and synchronization to one `rclone sync` command. A unique `--backup-dir` under `.sambinha/history/` retains replaced/deleted files until the larger of `deleted_days` and `version_days`; finalization lists immediate history directories and purges expired runs. `--max-delete` is an absolute per-job cap and the entire sync is not retried. Batch keys are immutable and derived from original indexed metadata; the planner reuses compatible intact archives. Worker threads own separate subprocess state and staging. The main thread publishes the recovery index only after all uploads, then commits local state. Batch retention cleanup uses `index_pending` to retry publication after failures.

`filtering` freezes rules and delegates matching to rclone, including historical paths represented by empty files. For batch jobs with exclusions, source discovery calls non-recursive `lsjson` once per directory and applies rules to paths relative to the source root; the batch inventory is still assembled globally. Results are cached per Selection per execution. Legacy mixed excluded batches stay in `excluded`. `retention` stores deadlines/original paths and aggregates advisory warnings; the separate removal guard blocks large inventory losses before strategy execution. `mounts` checks pinned nonempty volumes, and `disks` rejects local filesystems above 95% occupancy before backup and destination changes.

`recovery` dispatches recovery actions, handles locking/logging/failure policy and preserves its original function imports. `recovery_index` reads local indexes or a bounded remote recovery member; `archive_recovery` validates checksums and safe archive members before extraction. `restore` stages selected files and publishes only after all checks pass; `verification` handles native checks, local archive integrity and S3 object metadata. Simple verification invokes `rclone check`; batch checks verify archives and controls. S3 batch verification only calls metadata stat. Only successful scheduled batch checks update their timestamp.

`progress` displays throttled stage/directory/percentage updates only on interactive stderr. Simple sync uses rclone's live stats; batch inventory counters use files/bytes and other opaque subprocesses use bounded estimates. `logging` clears the transient line before printing JSON; progress has no audit event.

The writer lock covers backup execution and manual verification. Restore reads an atomic index snapshot and fails if a concurrently retired object is unavailable. Without filesystem snapshots, concurrent source changes can interrupt a backup. Jobs are independently committed; there is no distributed transaction across jobs. Overlapping jobs follow TOML order and may invalidate each other's indexes or overwrite a shared remote recovery control; preserving local state and using dedicated prefixes avoids those interactions. Fingerprint reuse assumes honest local filesystem metadata; complete periodic scans are the fallback.
